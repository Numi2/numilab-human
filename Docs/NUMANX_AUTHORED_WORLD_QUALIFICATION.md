# NumanX authored-world qualification

The permanent NumanX joint runtime now loads authored, compiled Matter worlds.
It no longer requires the hard-coded one-tet fixture. The owning C++ runtime
validates the package and its Human binding, then uses the existing device
transaction for preparation, proof, rollback, application and publication.
The Swift bridge and Gate C capture tool expose the same path.

**Numi Human is still incomplete.** This qualification establishes package
admission and joint transactions over 0.8 ms per integrated test. It does not
establish sustained standing, walking or anatomical tissue fidelity.

## What changed

Native configuration v3 accepts an existing Matter package, a matching Human
source fingerprint and an exact cooked-world fingerprint. It rejects missing,
corrupt, stale or incompatible inputs instead of constructing a fallback world.
The existing Matter package format and compiler retain ownership. Metadata
reports whether the loaded world is authored or the legacy fixture.

Admission checks the environment and capacity class, timestep, gravity,
deterministic execution, supported topology, two-way coupling and initial
attachment positions/velocities against the exact Human body frames. Attachment
capacity is derived from the package. The world remains resident after its
source file is removed.

Nonzero active-fibre tension is rejected until a replacement map removes the
corresponding MyoSim force share. General rigid proxies, adaptive topology and
joint-equality coupling remain outside this admitted interface. Stored material
parameter priors are permitted with online identification disabled. Source
muscle force ownership and the existing accepted-step transaction are preserved.

The Swift capture interface selects an authored world with:

```text
--matter-world PATH --human-source-fp HEX --matter-world-fp HEX
```

The rest of the Human asset, policy, run-identity and timestep arguments remain
required. See the owning
[NumiBrain guide](https://github.com/Numi2/numi-brain/blob/45d63b51c2d98e83cebce5264472192b86095d46/docs/NUMANX_AUTHORED_MATTER.md).

## Build and rejected development evidence

The fresh SwiftPM build exposed inaccessible cross-module evidence helpers,
two test compilation errors, and macOS temporary paths that Foundation left
symlinked despite `resolvingSymlinksInPath`. The fixes use package-level helper
visibility and POSIX-resolved test directories. Production file protections
remain intact. The focused tests then passed on macmini.

MLX also required its separately cooked support metallib. The new owning build
script creates it from the exact pinned dependency and installs it beside the
CLI and XCTest executables. The original
[missing-resource failure](media/numanx-authored-world-20260908/missing-mlx-resource.log),
[temp-path failures](media/numanx-authored-world-20260908/unresolved-temp-path-tests.log)
and [overstrict admission failure](media/numanx-authored-world-20260908/rejected-admission-development.log)
are retained. The final successful run did not time out; buffered XCTest output
briefly made it appear stalled.

## Remaining completion work

The first integrated standing/walking gate still requires the source joint
constraints in the coupled operator, registered anatomical pressure contact,
authored tissue geometry with source mass/force partitioning, and a causal
closed-loop muscle controller. Regional NHFASC assets must be lowered into the
production artifact path with those ownership contracts; loading a generic
Matter package alone does not perform that integration.

Standing for 60 seconds across 20 seeds, frozen perturbation recovery, and the
120-second walking distributions remain unrun. The full target also retains
its source-coverage catalog, systemic physiology, skin/organ/vessel/nerve
mechanics, calibration, uncertainty and measured Apple-runtime requirements.
The [completion ledger](HUMAN_COMPLETION_GAP_LEDGER.md) remains authoritative
about these open claims.
