# Support/contact attribution correction for the baseline drift note

This is a source-owner interpretation addendum to baseline-drift.json; it does not change the baseline evidence or qualify it. The measured late COM drift remains unexplained by the current exported fields: about -0.515 mm/min in world X over the 250–310 s window. The static NHCNT seed-ID column cannot establish whether the dynamic selected skin witness changed, and the support impulse rows do not report point slip.

The current scene does not use a separate fixed skin collision mesh. The NHCNT payload defines 32 point-query slots/seed metadata and the existing stand contact solver remains the force owner. At each physical step, NumiHumanRestingVisual constructs the support program from the registered NHSKIN vertex map, influences, and region assignment. The Metal support kernels evaluate the full registered skin at current articulated body poses, choose a deterministic minimum-height vertex per region, and publish that weighted skin point plus Jacobian into the NHCNT point query. This is discrete point support derived from NHSKIN, not triangle-mesh collision. Consequently, a change to NHSKIN927 can move the actual support points and alter their contact Jacobians even when the NHCNT slots remain fixed; any revised skin candidate must preserve/requalify this support behavior.

There is no --q-diagnostic-stride option in this frozen source. NUMI_HUMAN_ACCEPTED_Q_INTEGRATION_AUDIT=1 writes full q/v before, preprojection, and accepted arrays at every accepted root, but requires the COM audit segment length to be one. It was disabled in the registered baseline. The baseline's existing cadence-8 COM observer already calls computeArticulatedBodyKinematics for every body, but retains only aggregate COM and root velocity; it does not export the per-body kinematics. The optional NUMI_HUMAN_SUPPORT_DIAGNOSTICS=1 debug writes the selected skin vertex, query point, and maximum absolute Jacobian at step 0 only. Neither the baseline support CSV nor its 8-root observer exports the late dynamic selected vertex or contact-point tangential relative velocity.

The support geometry kernel consumes body poses/body-position lows, skin mappings, and skin influences; it does not consume a respiratory modal coefficient or modal displacement field directly. Respiratory excitation may alter articulated body q/v, which can move the skinned point and change its Jacobian indirectly. The accepted point-contact impulse also enters the articulated stand solver through the ordinary generalized contact Jacobian. This establishes an indirect kinematic/contact path, not a direct respiratory-mode reaction term or a measured respiratory-to-cardiovascular pressure-feedback path.

The smallest useful follow-up is a read-only observer extension at the existing 8-root cadence: record per-body COM position/orientation and linear/angular velocity from the already-computed FK, and for each NHCNT slot record the GPU-selected NHSKIN vertex ID and weighted world point at the same physical pre-step contact evaluation. Record J(q)·v for that selected point, projected onto bed-normal/tangent axes relative to bed velocity, with exact accepted-step/pre-step-basis labels. This is what would distinguish selector changes, tangential sliding, and articulated settling. It is not implemented in this note. The separately prepared 32-vs-64 full-horizon run can test iteration sensitivity after the active treatment arm closes; it cannot substitute for these observations or prove a unique cause.
